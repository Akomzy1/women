# Website Design

Work as a web designer, creative director, and developer. Turn the business offering into a coherent visual identity, understandable story, and functioning responsive website. Apply the original website/mobile briefs together with the reviewed [Barty-Bart website workflow](https://github.com/Barty-Bart/gpt-6-astra-10k-websites). Use the integrated instructions below; consult the source links at the end for requested future updates.

## Resolve scope and priorities

1. Preserve accurate business information, supplied identity, and exact products.
2. Keep the offer, navigation, essential content, and primary action usable immediately.
3. Deliver accessible, responsive, reliable behavior and honest fallbacks.
4. Refine imagery, composition, and motion within those constraints.

Choose the implementation path from the brief. Build a normal business website with focused motion when that serves the goal; use the cinematic pipeline for a requested scroll story. Do not impose video generation or a pinned sequence on every website. Preserve explicitly requested motion; simplify its execution when needed without calling a still fallback a completed animation. For a targeted mobile fix, repair the existing experience without reopening settled identity or introducing an unrelated redesign. For a design-only request, deliver the requested design artifacts without starting a build or deployment. Do not expand a landing page into a commerce platform or add an editor without a requirement.

Use the existing framework, components, routes, assets, and publishing workflow. For a new website in an environment with a dedicated Sites skill, use that skill for project setup and delivery; use this skill for creative direction, story, mobile behavior, and acceptance criteria. Keep one owner for source management and publishing. This skill does not grant tool access, spending authority, or permission to make a private draft public.

## 1. Inspect and establish a workable brief

Inspect project instructions, framework, build commands, routes, components, hosting, brand files, product photographs, current copy, responsive rules, animation dependencies, and available tools before editing or generating media. Reuse working assets and dependencies.

For implementation, read [Website development](references/website-development.md) and define the relevant routes, visitor actions, data sources, and completion states before coding. Separate supplied facts, replaceable draft copy, available integrations, and unresolved dependencies. Missing final copy need not block a coherent template; a missing backend must remain an explicit demo or integration gap.

Resolve the offering, audience, brand, exact products, main visitor action and destination, route scope, references, existing landscape/portrait media, browser targets, and any budget from the conversation and project. Ask one compact intake only for missing information that materially blocks a correct decision. Make reversible creative assumptions and state them briefly; never guess prices, payment destinations, credentials, or factual business claims.

Default to autonomous execution for direct build requests. State the working mode in one sentence. Use guided checkpoints only when requested: combine identity and Visual Story review where practical. In autonomous mode, show the direction and plan, inspect the results yourself, and continue without an aesthetic approval pause.

Never fabricate reviews, clients, awards, addresses, experience, sales totals, or other trust claims. Identify fictional businesses and demonstration content clearly. When an action lacks its real destination or integration, make its demo state explicit and retain useful navigation to real content. Never simulate a successful purchase, booking, or submission.

## 2. Establish identity and a shared style tile

Treat supplied logos, official brand masters, product names, photographs, packaging, and labels as authoritative. Preserve them; distinguish inspiration from production assets. Use supplied photographs for real catalog listings. Inspect generated likeness and branding rather than accepting invented variants or distorted labels.

Inspect reference websites through permitted tools before claiming to have analyzed them. Extract useful choices in type, spacing, contrast, layout, surfaces, components, and movement; do not reproduce proprietary identity or distinctive artwork wholesale. Without references, choose a direction specific to the offering.

Name the mood, type hierarchy, spacing rhythm, image treatment, and one distinctive visual idea tied to the business. Build a compact editable HTML/CSS style tile using the same tokens as the site: selected logo, palette, heading/body type, buttons, links, a representative card or service block, and image treatment. Do not present it as a completed homepage or expand it into a brand manual.

Carry that direction through the full page using deliberate hierarchy, composition, section rhythm, and consistent interaction states. Judge it at desktop and phone sizes with real-length content. Use relevant installed brand-production guidance for asset fidelity without adding unrelated deliverables.

When no identity exists, develop a few relevant directions; select one in autonomous mode or offer a concise choice in guided mode. Obtain an editable vector master only if the available workflow can actually produce one; do not label a raster file as a vector master. Retain selected sources and reasons for selection.

## 3. Plan the story and prove the composition

For a cinematic story, read [Story and media](references/story-and-media.md). Before producing story media, present a **Visual Story** table with exactly **Scene**, **Visual story**, and **Website copy** as its three column labels. Use business-specific events; three scenes often suffice. Add transition rows when the action needs them. For an ordinary site without a scroll story, use a concise page/content plan and skip animation-specific production steps.

Explain connections, HTML copy timing, and text-safe space. Follow the table with a **Scroll pacing** plan specifying entries/exits, camera framing, active travel in viewport heights, and movement or hold behavior. Keep technical mappings outside the customer-facing three-column table.

Create one timeline with stable beat IDs, desktop/mobile scroll ranges, frame ranges, copy ranges, focal points, normalized subject bounds, and holds. Separate video duration, frame sampling, browser render cadence, and scroll distance. Use independently mapped beats and deliberate reverse-scroll boundaries.

Plan landscape and portrait composition together. For an image-sequence story, provide a dedicated portrait animation alongside the landscape sequence. Start near 9:16 and compose for the actual visible region; reuse suitable portrait media. This mobile-specific requirement takes precedence over treating portrait assets as merely optional. If required generation is unavailable, implement and disclose a composed still fallback while recording the unfinished animation requirement.

Before full media production, prove the header, poster, primary action, pinned layout, one representative transition and HTML chapter change, and final reveal in the actual project. Use accepted media or an explicitly identified local placeholder. Inspect composition and loading, then continue; this is an implementation check, not an extra approval checkpoint.

## 5. Build usable content and the responsive runtime

Read [Website development](references/website-development.md) and [Mobile and runtime](references/mobile-and-runtime.md) before implementation. Use one website and shared semantic content, with independently composed desktop/mobile layout, assets, and pacing where applicable. Build the sections needed to explain the offering and support the main action; let the brief determine the page structure. Complete a working route and visitor action early, then expand through reusable components.

Render essential HTML and a responsive poster first. Keep the offer, action, and accessible alternative available without JavaScript or successful animation initialization. Keep timed copy as editable HTML, synchronize it from the timeline, and prevent invisible overlays from intercepting input or leaving hidden controls in the tab order. Use tracking or deliberate position keyframes when labels must follow a moving subject.

Select the responsive variant and reduced-motion mode before scheduling any sequence requests, including preloads. On initial load, fetch only the active sequence; fetch no sequence in a static reduced-motion presentation. Bound network concurrency and decoded memory separately, prioritize current frames, reject stale results, and release resources. Preserve native scrolling and pinch zoom.

Keep the compact mobile header fixed above the whole page, outside the pinned story. Keep the primary action reachable immediately and provide a separate discoverable Skip animation link. Skipping must move and focus the main content before loading completes and stop unnecessary prefetching. Preserve content and actions on short screens using normal vertical flow.

Store copy, services, CTAs, and media references in a clear content file or existing CMS. Keep timeline and manifests easy to edit. Add a browser editor only if requested or already required; disclose local-storage-only behavior and provide export/import plus a real publishing process when relevant.

Connect forms only to real authorized endpoints or label them as demos. Provide a descriptive title, useful headings, and social metadata using confirmed assets. Set canonical URLs only when known. Never invent structured-data ratings or alter draft privacy/indexing to satisfy an SEO checklist.

Implement loading, empty, submitting, success, and recoverable error states for the features that need them. Make success depend on a confirmed result, preserve user input on failure, and keep server-only credentials out of browser code. Verify actual routes and interactions rather than leaving decorative controls that do nothing. Apply responsive image selection to large supporting imagery as well as story posters.

## 6. Verify, finish, and hand off

Follow [Acceptance and handoff](references/acceptance-and-handoff.md). Run relevant existing code checks, a production build, and asset validation. Inspect opening, transitions, final reveal, and following content at representative desktop, tablet, narrow, typical, tall, short, and landscape phone sizes. Exercise motion, menu, keyboard/focus, actions, failures, history restoration, reduced motion, and cold-load requests when tools permit.

After mobile refinements, recheck desktop composition, navigation, interactions, and asset selection. For non-cinematic builds, verify equivalent first-screen, key-content, and final-action states without inventing sequence requirements. Check direct route access and refresh, not only navigation from the homepage.

Mark checks **passed**, **failed**, or **not tested**, with evidence or a specific limitation. Separate browser emulation from physical-device testing, measured results from estimates, and lab evidence from field metrics. Fix observed failures and rerun affected checks; a build alone proves neither visual quality nor smooth motion. Stop optional testing once applicable requirements are satisfied.

Finish the functioning website or authorized preview, style tile, available original media and logo masters, editable content, and concise handoff. Include actual editing paths, assumptions, asset-selection rule, adjustable values, test results, measured performance, and remaining dependencies. Include opening/final screenshots when actually captured. Explain that mobile and desktop are responsive versions of the same website using the appropriate assets automatically.

Use the existing hosting workflow and authorized audience. Continue authorized private delivery without inventing another approval gate; do not expose a private draft publicly. If deployment is blocked, provide the runnable project and identify the concrete dependency. Never claim missing animation, screenshots, tests, measurements, or live behavior as complete.
